# LeetCode 039. 组合总和 (Combination Sum)

## 1. 题目描述
给你一个 **无重复元素** 的整数数组 `candidates` 和一个目标整数 `target` ，找出 `candidates` 中可以使数字和为目标数 `target` 的所有 **不同组合** 。

* **重复使用**：`candidates` 中的同一个数字可以 **无限制重复被选取** 。
* **解集**：解集不能包含重复的组合（即组合中的元素相同，仅仅顺序不同也被视为重复）。
* **限制**：所有数字（包括 `target`）都是正整数。

**示例：**
> **输入**：candidates = [2, 3, 6, 7], target = 7
> **输出**：[[2, 2, 3], [7]]
> **解释**：2+2+3=7；7=7。

---

## 2. 题目分析

### 核心思想：回溯算法 (Backtracking) + 剪枝 (Pruning)
这道题是典型的组合问题。由于题目允许**重复选择同一个元素**，我们的递归逻辑与“子集”或“全排列”稍有不同。

1.  **决策树结构**：
    * 每一层我们可以从 `candidates` 中选一个数。
    * 为了避免结果重复（例如 `[2, 3, 2]` 和 `[2, 2, 3]`），我们需要维护一个 `start` 索引，规定下一层递归只能从当前索引或之后的索引开始选。
    * 因为可以重复选，所以递归到下一层时，`start` 索引**不需要加 1**，而是继续传入当前的索引 `i`。

2.  **剪枝优化**：
    * 如果我们将 `candidates` 数组先进行**排序**，那么在递归搜索时，如果当前的 `target` 减去某个数已经小于 0 了，那么后面的数（比当前的数更大）也就没必要再试了。这可以极大地减少搜索次数。

## 3. 代码实现 (Python)

```python
from typing import List

class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        res = []   # 存储所有符合要求的组合
        path = []  # 存储当前的搜索路径
        
        # 1. 为了剪枝，先对候选数组进行排序
        candidates.sort()
        
        def backtrack(remain: int, start: int):
            # 【结束条件】如果剩余目标值为 0，说明找到了一个合法组合
            if remain == 0:
                res.append(path[:])
                return
            
            # 从 start 开始遍历，避免产生重复组合
            for i in range(start, len(candidates)):
                # 【剪枝】如果当前数字已经大于剩余的目标值，后面的数字也一定大
                # 直接跳出当前循环，不再继续递归
                if remain - candidates[i] < 0:
                    break
                
                # 做选择
                path.append(candidates[i])
                
                # 递归：注意这里传入的是 i 而不是 i + 1
                # 因为同一个数字可以重复使用
                backtrack(remain - candidates[i], i)
                
                # 回溯：撤销选择
                path.pop()
        
        backtrack(target, 0)
        return res
```

## 4. 复杂度分析

### 时间复杂度：$O(S)$
* $S$ 是所有可行解的长度之和。回溯算法的时间复杂度通常很难精确界定，它取决于搜索树中节点的数量。
* 在最坏情况下，时间复杂度与 $N^{T/min\_cand}$ 相关（$N$ 为数组长度，$T$ 为目标值，$min\_cand$ 为数组中最小的数）。
* 排序和剪枝能大幅提高实际运行效率。

### 空间复杂度：$O(T/min\_cand)$
* **递归栈深度**：最坏的情况下，递归的深度取决于目标值 $T$ 被最小元素 $min\_cand$ 填满的次数，即 $O(T/min\_cand)$。
* **辅助空间**：`path` 列表的长度最大同样为 $O(T/min\_cand)$。
* （注：不计入存储最终结果集的空间）。
