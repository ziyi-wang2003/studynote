# LeetCode 001. 两数之和 (Two Sum)

## 1. 题目描述
给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值** `target` 的那 **两个** 整数，并返回它们的数组下标。

* **假设**：每种输入复且仅对应一个答案。
* **限制**：数组中同一个元素在答案里不能重复使用。
* **返回形式**：你可以按任意顺序返回答案。

**示例：**
> **输入**：nums = [2, 7, 11, 15], target = 9
> **输出**：[0, 1]
> **解释**：因为 nums[0] + nums[1] == 9，返回 [0, 1]。

---

## 2. 题目分析

### 暴力解法 (Brute Force)
最直观的想法是使用双重循环，遍历每一个数对，看它们的和是否等于 `target`。
* **缺点**：时间复杂度高达 $O(n^2)$，在数据量较大时会超时。

### 优化思路：哈希表 (Hash Map)
我们的核心目标是：当我们遍历到数字 `x` 时，能不能**快速找到**数组中是否存在 `target - x`？

1.  我们可以维护一个**哈希表（字典）**，用来存储我们“见过”的数字及其对应的索引。
2.  在遍历数组时，对于当前的元素 `nums[i]`：
    * 计算我们需要的目标补数：`complement = target - nums[i]`。
    * 检查这个 `complement` 是否已经在哈希表中。
    * **如果存在**：说明我们找到了这一对数，直接返回 `[complement的索引, i]`。
    * **如果不存在**：把当前的 `nums[i]` 和它的索引 `i` 存入哈希表，方便后续的数字来找它。



---

## 3. 代码实现 (Python)

```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        """
        使用哈希表进行优化，实现 O(n) 时间复杂度
        """
        # 创建一个字典，用于存储：{数值: 下标}
        hash_map = {}
        
        # 遍历数组，enumerate 可以同时拿到索引 i 和数值 num
        for i, num in enumerate(nums):
            # 计算当前数字需要的“补数”
            complement = target - num
            
            # 检查补数是否已经在字典中（即之前是否遇到过这个补数）
            if complement in hash_map:
                # 如果找到了，返回补数的索引和当前数字的索引
                return [hash_map[complement], i]
            
            # 如果没找到，将当前数字存入字典，等待“有缘人”来匹配
            # 键是数值，值是对应的索引
            hash_map[num] = i
            
        # 题目保证有解，所以这里理论上不会被触发
        return []
```

## 4. 复杂度分析

### 时间复杂度：$O(n)$
* 我们只需遍历数组一次，共 $n$ 个元素。
* 在哈希表中查找和插入元素的操作，其平均时间复杂度均为 $O(1)$。
* 因此，总时间复杂度为 $O(n \times 1) = O(n)$。

### 空间复杂度：$O(n)$
* 在最坏的情况下，我们需要将数组中除最后一个元素外的所有元素都存入哈希表。
* 哈希表所占用的额外空间与数组长度成线性关系，即 $O(n)$。
