## DeepSpeed ZeRO：大模型训练的显存优化与数据并行扩展

### 1 背景：训练大模型的显存瓶颈与数值精度体系

#### 1.1 训练时的显存构成

训练一个 Transformer 模型时，显存占用主要来自以下四部分：
- **模型参数（Weights）**：所有可训练参数的张量。
- **梯度（Gradients）**：与参数一一对应的梯度张量。
- **优化器状态（Optimizer States）**：如 Adam 中的动量（momentum）和方差（variance）。
- **中间激活值（Activations）**：前向传播中为反向传播保留的中间结果。

对于参数数量为 \(\Phi\) 的模型，采用混合精度训练（如 FP16 参数存储）时各部分显存可大致估算。然而更关键的是：**在标准数据并行中，每个 GPU 都保存一份完整的模型参数、梯度和优化器状态**。当模型参数达到数十亿甚至数千亿时，单卡显存无法容纳完整副本。ZeRO（Zero Redundancy Optimizer）的核心思想是**消除数据并行中的冗余存储**，将模型状态（参数、梯度、优化器状态）分片到所有数据并行进程中，在不改变计算精度的前提下近乎线性地扩展单卡可容纳的模型规模。

#### 1.2 数值精度格式简明介绍

在深入 ZeRO 之前，有必要理解现代训练中使用的各种数值格式。不同格式在**表示范围、精度和存储开销**之间权衡。

**浮点格式**
- **FP32（单精度）**：1 符号位 + 8 指数位 + 23 尾数位，共 32 位（4 字节）。表示范围约 \(1.4\times10^{-45}\) 到 \(3.4\times10^{38}\)，精度高但存储与计算开销大。通常作为基线或用于主权重（master weights）。
- **FP16（半精度）**：1+5+10，共 16 位（2 字节）。表示范围约 \(5.96\times10^{-8}\) 到 65504。问题在于**下溢出**：梯度幅值小于 \(2^{-24}\) 即变为 0。需要动态损失缩放（loss scaling）来缓解。
- **BF16（Brain Float）**：1+8+7，共 16 位。指数位与 FP32 相同（8 位），因此表示范围与 FP32 一致，但尾数精度降低。**关键优势**：无需损失缩放即可稳定训练，且与 FP32 之间的转换不损失指数范围。目前在新一代 GPU（A100、H100）上得到广泛支持。

**整型与低精度格式**
- **INT8**：8 位整数（1 字节），有/无符号。动态范围固定，通常通过**量化**（quantization）从浮点转换而来。在推理中广泛使用，训练中用于通信压缩或梯度量化。
- **INT4**：4 位整数，进一步压缩。用于模型量化推理或极端内存受限场景。
- **FP8（E4M3 / E5M2）**：8 位浮点，指数位 4 或 5，尾数位 3 或 2。NVIDIA H100 引入了对 FP8 的张量核心支持。E4M3 精度更高但范围小，E5M2 范围大但精度低。常用于训练中的梯度表示或激活压缩。
- **FP4**：4 位浮点，格式如 1+2+1。极小存储，主要用于极低比特推理，训练中极少直接使用。

在 ZeRO 上下文中，模型参数和梯度通常采用 **FP16 或 BF16** 存储和计算，优化器状态和主权重保留为 **FP32** 以累积精度。低精度格式（FP8、INT8）可在 ZeRO 的基础上进一步通过通信压缩或混合精度扩展来提升效率。

### 2 ZeRO 的设计动机与核心理念

标准数据并行（DP）中，每个 GPU 持有完整模型副本，每个 GPU 处理不同 mini-batch 数据，梯度经过 all-reduce 后一致更新。该方法无法训练超过单卡显存容量的模型。**模型并行**（MP、PP）可以分割模型，但存在通信开销大、负载不均衡、实现复杂等缺点。ZeRO 的目标是：**在数据并行的框架下，通过冗余消除使每个 GPU 只存储模型状态的一个分区，总容量随 GPU 数量线性增长**。

ZeRO 将模型状态划分为三类：
- **参数 \(\Theta\)**（Weights）
- **梯度 \(G\)**（Gradients）
- **优化器状态 \(O\)**（Optimizer States）

每类均可独立地进行分片（切分到所有 DP rank）。根据分片的粒度，ZeRO 定义了三个阶段：

- **ZeRO-1**（\(P_{os}\)）：仅分片优化器状态 \(O\)。
- **ZeRO-2**（\(P_{os+g}\)）：分片优化器状态 \(O\) + 梯度 \(G\)。
- **ZeRO-3**（\(P_{os+g+p}\)）：分片优化器状态 \(O\) + 梯度 \(G\) + 参数 \(\Theta\)。

每个阶段都对通信量和存储冗余有不同影响。下面分别详述。

### 3 ZeRO-1（\(P_{os}\)）优化器状态分片

#### 3.1 存储分析

以 Adam 优化器为例，对于每个参数，优化器状态包含**动量 \(m\)** 和**方差 \(v\)**，均为 FP32 类型。因此，显存构成可写为：
- 参数（FP16）：\(2\Phi\) 字节（假设 FP16 存储）
- 梯度（FP16）：\(2\Phi\) 字节
- 优化器状态（FP32 的 \(m\) 和 \(v\)）：\(4\Phi + 4\Phi = 8\Phi\) 字节
- 主权重（FP32，用于更新）：\(4\Phi\) 字节（有些实现不独立存储，而是用 FP16 参数转换后更新再转回）

粗略统计，FP16 混合精度训练时，每参数约占用 **\(2+2+8+4=16\) 字节**（若计入主权重）。实际上常见实现中，FP16 参数 + FP16 梯度 + FP32 优化器状态（\(m, v\)）+ FP32 主权重（可选），总计约 **20 字节/参数**。

ZeRO-1 将优化器状态 \(O\) 切分为 \(N_d\) 份（\(N_d\) 为数据并行度），每个 GPU 只存储 \(1/N_d\) 的 \(m\) 和 \(v\)，以及对应的那部分主权重（若使用）。因此优化器状态从 \(8\Phi\) 字节降至 \(8\Phi / N_d\)，主权重从 \(4\Phi\) 降至 \(4\Phi / N_d\)。每个 GPU 仍保留完整的 FP16 参数和梯度。每 GPU 显存占用近似为：
\[
2\Phi (\text{params}) + 2\Phi (\text{grads}) + \frac{12\Phi}{N_d}(\text{optimizer states} + \text{master weights})
\]
当 \(N_d\) 足够大时，后项可忽略，但前两项 \(4\Phi\) 仍构成瓶颈。ZeRO-1 适合中等规模模型扩展，通信量与标准 DP 相同（仍需 all-reduce 梯度）。

#### 3.2 计算流程

1. 每个 GPU 在其本地数据上计算前向和反向，得到完整的梯度（FP16）。
2. 对梯度执行 **reduce-scatter** 操作：每个 GPU 只获得自己负责那部分参数所对应的梯度分区（即梯度的 \(1/N_d\)）。这一步将梯度值按优化器状态分区的位置进行规约。
3. 每个 GPU 用其持有的优化器状态分区（\(m, v\) 分区）更新其负责的**主权重分区**（FP32），得到更新后的参数分区。
4. 更新后的参数分区被转换为 FP16，并通过 **all-gather** 操作广播到所有 GPU，使每个 GPU 恢复完整的 FP16 参数用于下一步前向。

引入的额外通信：一次 reduce-scatter（等价于 all-reduce 的一半） + 一次 all-gather。**总通信量与标准 DP 相同**（标准 DP 中 all-reduce 的通信量也是 \(2\Phi\) 每迭代，reduce-scatter+all-gather 总通信量相同）。

### 4 ZeRO-2（\(P_{os+g}\)）梯度分片

#### 4.1 核心机制

ZeRO-2 在 ZeRO-1 的基础上进一步分片梯度 \(G\)。每个 GPU 只存储与其优化器状态分区相对应的那部分梯度，即梯度的 \(1/N_d\)。这样做的前提是：在反向传播过程中，梯度一旦生成并被用于更新对应参数之后，就不再需要完整的梯度张量。

**关键洞察**：梯度的 all-reduce 可以分解为 **reduce-scatter**（各 GPU 获得自己分区的规约结果）和随后对更新参数的 **all-gather**。ZeRO-2 将 reduce-scatter 后的梯度直接保留在对应 GPU 上，用于本地优化器更新，然后丢弃其他分区的梯度。因此，每个 GPU 内存中不再保存完整的梯度张量，只保存 \(1/N_d\) 的梯度。

存储收益：从 ZeRO-1 的 \(2\Phi\)（全梯度）降至 \(2\Phi / N_d\)。每 GPU 显存近似为：
\[
2\Phi (\text{params}) + \frac{2\Phi}{N_d}(\text{grads}) + \frac{12\Phi}{N_d}(\text{optimizer states} + \text{master weights})
\]
参数本身仍是完整存储，这仍限制进一步扩展。

通信量：与 ZeRO-1 相同（reduce-scatter + all-gather）。实际上 ZeRO-2 并未增加通信。

#### 4.2 反向传播与通信重叠

ZeRO-2 的一项重要优化是**将梯度规约与反向传播计算重叠**。在反向传播逐层计算梯度时，一旦某一层的梯度就绪，即可发起该梯度分区的 reduce-scatter 操作，而不必等待整个反向传播结束。这种重叠可显著隐藏通信延迟。实现时需要对层的执行顺序与通信调度进行精细编排。

### 5 ZeRO-3（\(P_{os+g+p}\)）参数分片

#### 5.1 完整的模型状态分片

ZeRO-3 将参数 \(\Theta\) 也进行分片。每个 GPU 仅存储其负责的那部分参数的 FP16 权重，以及对应的主权重（FP32）。前向计算时，为了完成某一层的计算，该层所需的参数必须完整存在于当前 GPU。因此 ZeRO-3 引入了**参数收集与释放**机制：

- **前向传播**：在进入某一层之前，通过 all-gather 从所有 GPU 收集该层参数的全集。计算完成后，立即释放非本地的参数副本（或标记为可覆盖），节省显存。
- **反向传播**：类似地，在需要该层梯度时，重新 all-gather 参数；计算完本层梯度后，对各 GPU 上该层的梯度分区进行 reduce-scatter，存储本地梯度分区用于优化器更新，然后本层参数和梯度均可释放。

这种 **动态参数交换** 使得每个 GPU 在任何时刻只需存储一小部分参数（\(1/N_d\)），加上临时收集的当前层参数。显存占用从 \(2\Phi\)（完整参数）降至 \(2\Phi / N_d\)。最终每 GPU 显存近似：
\[
\frac{2\Phi}{N_d}(\text{params}) + \frac{2\Phi}{N_d}(\text{grads}) + \frac{12\Phi}{N_d}(\text{optimizer states} + \text{master weights}) + \text{activation memory}
\]
除激活值外，**模型状态随 GPU 数量线性缩放到极小值**。激活值内存可通过激活重计算（activation recomputation）进一步降低。

#### 5.2 通信开销的变化

ZeRO-3 引入额外的 all-gather 操作：每层前向一次，每层反向一次（用于重新收集参数）。相较于 ZeRO-2 中每迭代一次 all-gather（用于更新后同步参数），ZeRO-3 每层都通信一次。**总通信量约增加至原来的两倍**（每个参数在前向和反向各被广播一次），但仍是可接受的线性增长，且随模型加深而增加。实践中可通过**管道化**和**重叠**来缓解。

#### 5.3 与模型并行的比较

ZeRO-3 常被误认为是模型并行的一种形式，但其本质仍是数据并行——每个 GPU 处理不同的 mini-batch，只是模型参数被分片存储并按需收集。与需要精细切分计算图的张量模型并行（如 Megatron-LM）不同，ZeRO 对模型结构无侵入性，只需在通信层做 all-gather/reduce-scatter。ZeRO 可以与模型并行、流水线并行**混合使用**，实现超大规模训练（如 Megatron-DeepSpeed）。

### 6 扩展：ZeRO-Offload 与 ZeRO-Infinity

#### 6.1 ZeRO-Offload

ZeRO-Offload 将**优化器状态和梯度**的计算与存储**卸载到 CPU 内存**，利用 CPU 的内存容量（可远大于 GPU）和计算能力（虽然慢，但由于优化器更新占总计算量比例低，整体影响可控）。GPU 仅保留参数和前向/反向计算所需的激活。ZeRO-Offload 的设计区分了**计算密集型操作**（如矩阵乘法，留在 GPU）和**存储密集型操作**（如优化器更新，卸载到 CPU）。通信通过 PCIe 进行。对于单 GPU 无法容纳完整模型的情况（如 20B 模型），ZeRO-Offload 可在单卡上完成训练，显著降低硬件门槛。

#### 6.2 ZeRO-Infinity

ZeRO-Infinity 是 ZeRO-Offload 的扩展，支持将模型状态**同时卸载到 CPU 内存和 NVMe SSD**，突破了 CPU 内存容量的限制。它统一了参数、梯度和优化器状态的**无限卸载**（infinity offload），并引入**带宽感知的调度**（优先使用 CPU 内存，溢出至 SSD）。ZeRO-Infinity 能够在单 GPU 上训练比 GPU 显存大数千倍的模型（如 100B 参数量），代价是训练速度下降但对超大模型微调仍有实用价值。

### 7 实践中的配置与权衡

| 阶段 | 分片内容 | 显存节省 | 通信量变化 | 适用场景 |
|------|----------|----------|------------|----------|
| ZeRO-1 | 优化器状态 | 约 4 倍（对 Adam 为例） | 与 DP 相同 | 中等规模、优化器状态占主导 |
| ZeRO-2 | 优化器状态 + 梯度 | 约 8 倍 | 与 DP 相同 | 大部分大模型训练基线 |
| ZeRO-3 | 优化器状态 + 梯度 + 参数 | 线性扩展（\(N_d\) 倍） | 约 2 倍 DP | 超大规模（百亿至万亿参数） |

在 DeepSpeed 中，配置通过 `zero_optimization` 字典完成。例如：
- `stage=1`（ZeRO-1）
- `stage=2`（ZeRO-2，可开 `overlap_comm`）
- `stage=3`（ZeRO-3，可配 `sub_group_size` 控制粒度）
- `offload_optimizer`（ZeRO-Offload）与 `offload_param`（ZeRO-Infinity）进一步卸载。

**注意**：ZeRO-3 的参数收集会增加激活内存压力，因为需要同时保持当前层参数和部分激活值。实践中常结合**激活重计算**（activation checkpointing）以平衡。

### 8 总结

ZeRO 通过从优化器状态到梯度的逐级分片，最终实现参数的全分片，使数据并行从“内存冗余”走向“内存聚合”，在不改变模型架构的前提下，支持训练单卡无法容纳的超大模型。ZeRO-1 和 ZeRO-2 以最小通信开销消除优化器状态和梯度冗余，适合常规大模型训练；ZeRO-3 为超大规模（千亿以上）提供了线性扩展能力，代价为增加约一倍的通信。ZeRO-Offload 和 ZeRO-Infinity 进一步打破 GPU 显存物理边界，引入 CPU 和 SSD 作为内存层次，使有限硬件下训练超大模型成为可能。结合高性能通信重叠与混合精度（FP16/BF16）训练，ZeRO 已成为当今大模型训练的**事实标准内存解决方案**，并集成于 DeepSpeed、PyTorch FSDP（受 ZeRO-3 启发）等主流框架中。
